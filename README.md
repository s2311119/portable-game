# portable-game
```text
① 明らかなバグだけ直す
Skill初期化、ドロップ、item ID、経験値進化、最低ダメージなど。
以下
・Skill::dependence/category
・戦闘ドロップ処理
・ボス・特殊敵のアイテムID
・複数レベルアップ時の進化
・最低ダメージ/回復
② 進化システムを整理する
5系統をどう分岐させたいかを先に決めてからテーブルを書き直す。
③ ゲームバランスを数値で見る
各Lvの味方ステータス、敵ステータス、与ダメージ、必要戦闘回数などを表にして調整する。
④ 最後にリファクタリング
大量に残っている昔のコメントアウトコードを削除し、9,000行の .ino を少し整理する。
```

| 優先度 | 場所 | 今回の監査で見つかった問題 |
|---|---|---|
| **最優先** | 戦闘ドロップ | 敵ごとに `dropItemId/dropRatePercent` を持っているのに、勝利時は**無条件でリペアキット(ID100)を1個追加しているだけ** |
| **最優先** | 進化 | 複数レベル一気上げで、**進化を1段階しか処理しない** |
| **最優先** | 進化 | レベル進化とアイテム進化の分岐仕様が現在のテーブルでは矛盾/曖昧 |
| **高** | 進化 | `Automaton::who/name` と `Status::who/name` が二重管理され、進化後に前者が古いままになる |
| **高** | 進化素材 | 特殊進化でID19を要求するが、`createItemById()` に**ID19が存在しない** |
| **高** | バフ | 挑発・かばう・ステルス・カウンターなど、**ターン数が減っていない特殊バフが大量にある** |
| **高** | 反射 | `reflectAllTurns=1` がセットされるが、**反射しても減らず、UpdateTurnでも減らない** |
| **中～高** | 防御 | 「物理ダメージを1にする」効果が、実際には**全ダメージを1にしている** |
| **中** | 店 | 店のTier計算が `floor / 10` なので、コメントの「1～10F=Tier0」とズレて**10FでTier1**になる |
| **中** | 描画 | 8×8の町・9×9のボス部屋で、画面外部分を黒クリアせず `continue` しているため**前の描画が残る可能性** |
| **中** | マップ | `random(15, max_w / 2)` に `max_w=20` を渡しており、実質 `random(15,10)` になる |
| **仕様確認** | セーブ | セーブは現在マップそのものを保存せず、ロード時に**同じ階を新規ランダム生成**する |
| **低～中** | スキル | ID122「かく乱」のコメントと実装不一致 |
| **保守性** | 全体 | 9,537行 `.ino` 集中。これはバグ修正後に着手でよい |
